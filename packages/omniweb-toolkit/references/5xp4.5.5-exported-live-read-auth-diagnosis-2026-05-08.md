# 5xp4.5.5 — Exported live-read auth diagnosis (2026-05-08)

## Scope
Diagnose why `packages/omniweb-toolkit/scripts/check-research-agent-live-read.ts` failed with HTTP 401 on `/api/scores/top` while the maintained starter-loop path had previously produced a successful live-read artifact.

## Initial failing symptom
- Exported proof script: `node --import tsx packages/omniweb-toolkit/scripts/check-research-agent-live-read.ts`
- Failure: `HTTP 401 for https://www.supercolony.ai/api/scores/top?minScore=100&limit=10`
- Prior maintained artifact: `packages/omniweb-toolkit/references/artifacts/5xp4.5/5xp4.5.2-starter-loop.json`

## What was actually wrong
Two stacked defects existed in the exported live-read starter path:

1. **Wrong auth strategy for a protected endpoint**
   - `runtime/minimal-live-read-starter.mjs` used `createClient()` as a bare read-only client.
   - `/api/scores/top` requires a bearer token.
   - The starter-loop/runtime path can obtain or refresh auth via wallet-backed runtime state, but the exported live-read starter was not attaching the cached SuperColony token at all.

2. **Wrong default colony host in the exported starter path**
   - The exported starter fallback default was `https://www.supercolony.ai`.
   - The cached bearer token in `~/.supercolony-auth.json` was accepted on `https://supercolony.ai` but rejected on `https://www.supercolony.ai`.
   - Direct verification from this host:
     - `Bearer token + https://supercolony.ai/api/scores/top?...` => **HTTP 200**
     - `Bearer token + https://www.supercolony.ai/api/scores/top?...` => **HTTP 401** `Authentication required`

## Important non-root-cause truth surfaced during diagnosis
A first attempted patch swapped the exported starter to `connect()` from `omniweb-toolkit/runtime`. That exposed a separate problem:
- the wallet/runtime path currently depends on `RPC_URL=https://node3.demos.sh/`
- that RPC endpoint was returning **HTTP 502** from this host during diagnosis

That path is therefore not an acceptable dependency for the exported **live-read** proof. The proof must remain decoupled from wallet/runtime connectivity.

## Fix applied
### Exported live-read starter
`packages/omniweb-toolkit/agents/openclaw/research-agent/skills/omniweb-research-agent/runtime/minimal-live-read-starter.mjs`
- reverted away from `connect()`
- kept the starter read-only
- loaded cached bearer token from `~/.supercolony-auth.json`
- attached the token via a custom fetch wrapper passed into `createClient()`
- used the colony fallback URL instead of hard-coding the wrong host
- removed `balance` from the exported live-read proof surface because `/api/balance` on `https://supercolony.ai` returned 404 and the live-read proof contract does not require wallet-balance verification

### Default colony host normalization
Updated defaults from `https://www.supercolony.ai` to `https://supercolony.ai` in:
- `packages/omniweb-toolkit/agents/openclaw/research-agent/skills/omniweb-research-agent/runtime/capability-detect.mjs`
- `packages/omniweb-toolkit/src/starter-runtime-config.ts`

## Durable conclusion
The original 401 was **not** caused by stale credentials or endpoint-specific token scope drift. It was caused by an exported live-read proof path that:
- failed to attach the cached SuperColony auth token, and
- defaulted to the wrong host (`www.supercolony.ai` instead of `supercolony.ai`).

The corrected exported live-read proof is now explicitly read-only again and passes without depending on wallet/runtime connectivity.
