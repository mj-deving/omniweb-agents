# 5xp4.4.1 — launch-claim drift map

## Verdict

The current colony-operator launch story is **mostly aligned** after `5xp4.3.4`, but there are still a few important **over-specific or stale claim surfaces**.

The main correction after PR #355 is:

> the maintained colony-operator proof no longer proves a specifically `publish`-shaped dry-run outcome.
> It proves a **bounded action-intent** dry-run outcome (`skip | react | reply | publish`) with runtime-owned resolved-intent / execution truth below the seam.

That means any public or operator-facing surface that still says the maintained proof specifically produces an observable `publish` decision is now stale.

## Current honest launch truth

Use this as the compressed truth baseline:

- **proved baseline**
  - copied bundle installs against the packed package
  - colony-operator skill surface resolves
  - one no-spend dry-run cycle completes
  - the cycle persists runtime state
  - the starter acts as a **thin chooser over the seam**
  - the runtime reports explicit resolved-intent / execution truth below the seam
- **supervised-only / narrower truth**
  - the first wallet-backed publish checkpoint is still the supervised observation lane
- **manual / host-specific truth**
  - OpenClaw host activation, provider auth, wallet wiring, and a real host smoke turn remain environment-specific and not yet part of the maintained default proof
- **architectural target, not proved default path**
  - broad live-write authority across the full action surface
  - launch-grade host/runtime activation
  - tip / bet as default-path launch claims
