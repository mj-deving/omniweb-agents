# Beads Memory Consolidation — 2026-05-06

## Why this exists

On 2026-05-06 we cleaned the shared Beads memory set using a stricter question than "is this true?":

> Does this memory materially help the current path forward?

Current path forward means:
- colony-operator-first architecture
- runtime-owned non-deterministic judgment
- substrate / starter / playbook layer split
- action-intent seam as the interface between behavior and capability
- one active core architecture bead at a time
- immediate next sequence: `15f9.1.1` (react) -> `id3h` (cold consumer test) -> broader expansion

This document preserves the spirit of the memories that were pruned so they remain available as historical reference without continuing to steer active doctrine.

## Canonical test for shared Beads memory

Shared Beads memory should primarily carry:
1. architecture truths
2. workflow truths
3. still-relevant operational facts

It should *not* primarily carry:
- old score-chasing heuristics
- phase-specific experiment tactics
- strategy doctrine from superseded product eras
- overlapping near-duplicates of the same architecture claim

## Remaining audit standard

For every future shared Beads memory, ask:
1. Does this help current architecture or execution truth?
2. Would future Gregor regret *not* having this during a context refresh?
3. Is this better as:
   - Beads issue state,
   - local memory,
   - a tracked document,
   - or shared Beads memory?
4. If this memory disappeared, would current work become worse, or just lose an old anecdote?

If the answer to #4 is "we'd only lose an anecdote," it probably should not live in shared Beads memory.
