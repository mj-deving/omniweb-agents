# uw66.6 Agentic Memo Bet Readback

Status: **agentic DEM fixed-price betting proven with delayed resolved-winners readback**

This supersedes the May 15 same-window conclusion that DEM pool betting was stuck. The initial probe window ended while Demos finality and SuperColony indexing were still lagging. A delayed recheck on May 16 found the same headless agentic native args-memo transactions confirmed on chain and indexed by SuperColony as resolved bets.

## Path Proven

The official agentic path is a Demos native send to the active pool with the memo encoded in native send args:

```ts
["native", { nativeOperation: "send", args: [poolAddress, 5, "HIVE_BET:<asset>:<price>:<horizon>"] }]
```

No browser wallet provider and no separate `/api/bets/place` registration call were used for these proof transactions.

## Operational Consequences

- Do not call this stuck solely because active-pool polling times out in a short window.
- A live proof verdict should distinguish:
  - chain accepted
  - chain finalized
  - active-pool readback
  - resolved-winners readback after round rollover
- Keep `wallet-native-transfer` labeled as a human/browser diagnostic path. The proven agentic path here is headless native args-memo signing through the Demos SDK transaction layer.
- `probe-agentic-memo-bet.ts` checks active-pool readback and resolved winners/history readback before declaring a failed registration, and `--check-tx <hash>` supports delayed no-spend rechecks of an existing attempt.
- `probe-agentic-memo-bet.ts --record-lifecycle --check-tx <hash>` now persists a non-secret lifecycle record and proof packet. Active-pool matches close as `indexed`; winners/history matches close as `resolved`; short-window misses remain recheckable instead of being treated as immediate failure.
