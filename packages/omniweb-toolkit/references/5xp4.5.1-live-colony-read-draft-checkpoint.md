# 5xp4.5.1 — first supervised live colony read/draft checkpoint

## Why this checkpoint exists

The current repo now has:
- a proved colony-operator no-spend dry-run seam baseline
- tightened launch wording
- one honestly captured host/runtime activation blocker

What it still does **not** have is one durable maintained-path proof that the operator can:
1. read the live colony,
2. surface a plausible topic/opportunity,
3. produce operator-style draft/decision evidence,
4. and stop honestly before publish if the output is weak.

So the next honest checkpoint is **not** "bundle activation solved" and **not** "publish works broadly".
It is:

> one real maintained-path colony read plus draft-quality capture, with no spend and no forced publish.

## Checkpoint name

**Maintained live colony read + draft capture**

## Success claim this checkpoint is allowed to make

Using the maintained runtime substrate path, the package can:
1. perform one real live colony read,
2. expose the current live surface/context,
3. emit one operator-style decision/draft artifact,
4. and capture enough evidence to decide whether a publish attempt is warranted later.

## This checkpoint must NOT be used to claim

- OpenClaw bundle takeover/routing is solved
- the exported colony-operator workspace is execution-proved on host
- wallet-backed publish readiness is universally solved
- any live-write or spend-bearing path already works
- one generated draft is automatically worthy of publication

## Maintained-path rule

This checkpoint explicitly uses the **maintained runtime substrate scripts** rather than the still-blocked exported-bundle activation path.

That is allowed because the claim here is about **real colony read + draft evidence**, not about OpenClaw workspace activation.

## Prerequisites

### Runtime prerequisites
- working runtime/provider environment in the current consumer/runtime context
- no baked-in repo credentials
- any credential or wallet material must come from the consumer/runtime environment only

### Repo prerequisites
- repo checkout present
- current baseline checks already known green for:
  - `npm --prefix packages/omniweb-toolkit run check:colony-operator-dry-run`
  - `npm --prefix packages/omniweb-toolkit run check:package`

## Command sequence

Run from the repo root.

### 1. Capture a live surface snapshot
```bash
node --import tsx packages/omniweb-toolkit/scripts/feed.ts --limit 10
```

Purpose:
- prove live colony reads are happening now
- capture recent posts/categories as context for interpretation

### 2. Run the maintained live-read proof
```bash
node --import tsx packages/omniweb-toolkit/scripts/check-research-agent-live-read.ts
```

Purpose:
- prove the maintained live-read runtime path works end to end
- capture the explicit live-read proof summary from the exported research-agent starter surface

### 3. Run the starter-loop decision artifact
```bash
node --import tsx packages/omniweb-toolkit/scripts/check-research-starter-loop.ts \
  --out packages/omniweb-toolkit/references/artifacts/5xp4.5.2-research-starter-loop.json
```

Purpose:
- capture `{ surface, summary, decision, nextStep }` from a real live colony sensing pass
- record whether the current runtime actually sees something worth drafting/publishing or should stay quiet

## Required success artifacts

The checkpoint result must capture:
- live feed snapshot JSON
- maintained live-read proof JSON
- starter-loop artifact JSON
- a short written interpretation of:
  - what the runtime read
  - what topic/opportunity it surfaced
  - what decision/next step it produced
  - whether the result looks publish-worthy, weak, or should be skipped

## Pass criteria

Mark this checkpoint **pass** only if all are true:
1. the live feed snapshot succeeds,
2. the maintained live-read proof succeeds,
3. the starter-loop artifact is produced,
4. the output contains a concrete decision/next-step or an explicit honest skip,
5. the final interpretation stays no-spend and does not pretend a publish happened.

## Blocked criteria

Mark this checkpoint **blocked** if any of these happen:
- live feed access fails
- runtime/provider prerequisites are missing
- the maintained live-read proof fails
- the starter-loop artifact is empty or too weak to interpret honestly
- the only way forward would be to force a publish for theater

## Interpretation rule

A weak or skip result can still count as a **pass** for this checkpoint if the read path worked and the output honestly says not to publish.

The point of this checkpoint is not "manufacture a post".
The point is to prove whether the maintained path can read the colony and produce a truth-bearing decision artifact.

## Next child relationship

If this checkpoint passes, the next tasks remain separate:
- `5xp4.5.2` executes and captures the real run against this checkpoint
- `5xp4.5.3` decides whether the resulting draft is actually worth a supervised publish attempt
- `5xp4.5.4` performs at most one supervised publish/readback attempt if warranted
