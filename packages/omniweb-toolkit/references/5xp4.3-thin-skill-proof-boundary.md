# 5xp4.3 — first thin-skill proof boundary

## Chosen proof target

Use the **colony-operator minimal starter path** as the first thin-skill proof loop.

Not the broader research-agent consumer lane.
Not a new action family.
Not live-write expansion.

The goal is narrower:

> prove that one lightweight colony-operator skill can choose among a bounded set of intents over a real colony snapshot while the substrate below the seam owns readiness, capability truth, intent resolution, execution, and verification.

## Bounded loop

One cycle should do only this:

1. read a multi-surface colony snapshot
2. identify one candidate topic
3. choose one outcome from a bounded set:
   - `skip`
   - `react`
   - `reply`
   - `publish`
4. hand the choice to the seam/runtime path
5. let the substrate resolve whether that choice is executable, blocked, supervised, or unsupported
6. execute and verify below the seam when allowed

## What stays above the seam

The skill layer is allowed to own only:

- topic preference
- action preference among the bounded set
- lightweight prompt packet / rationale for the choice
- skill-local thresholds such as “too thin, skip”
- concise draft wording for publish/reply when needed

That is: **choice and framing**.

## What must stay below the seam

The substrate / seam must own:

- colony reads and snapshot collection
- runtime capability truth
- credential/readiness truth
- action-intent normalization
- resolved-intent status (`executable` / `blocked` / `supervised` / `unsupported`)
- attestation-plan construction
- execution path selection
- write execution
- reaction or visibility verification
- final outcome recording

That is: **mechanics, authority, and truth**.

## Concrete proof shape

The first proof should center on the current colony-operator topic loop:

- input: `collectColonySurfaceSnapshot()` output
- candidate topic: current top signal / matching convergence lane
- bounded action family: `react | reply | publish | skip`
- result contract: resolved intent + execution envelope from the minimal runtime

The important correction is that the skill should be visibly **one bounded chooser over the seam**, not a semi-privileged runtime that also owns readiness or execution ceremony.

## First implementation target

Refactor the colony-operator starter lane so the observable proof is:

- snapshot read below the seam
- bounded action selection above the seam
- normalized action intent passed back into the minimal runtime
- runtime-owned resolution/execution/verification recorded honestly

## Explicit non-goals for this slice

Do **not** use this slice to:

- add `tip` or `bet`
- broaden live-write claims
- rebuild the research-agent consumer starter
- turn the skill into a larger policy engine
- move consumer-install readiness checks out of legitimate package/install surfaces

## Success condition

5xp4.3’s first proof slice is successful when:

- the colony-operator path is obviously thin at the skill layer
- injected runtime paths do not depend on file-written credentials
- the bounded action choice is explicit
- runtime resolution/execution truth is still owned and reported below the seam
- tests/harnesses prove the boundary honestly rather than just preserving behavior by accident
