# uw66.14 — Node/API live-write divergence blocker truth (2026-05-12)

## Why this note exists

The first bounded live publish lane (`uw66.1`) exposed an upstream blocker that should be encoded as runtime truth rather than treated like a normal operator retry loop.

## Observed split

### Node3 / DAHR-Web2 path
- Raw DAHR/Web2 proxy probes on `node3.demos.sh` could create a session but `startProxy()` timed out or returned `504` for public URLs that were otherwise reachable from the host.
- This means a passing static preflight alone does **not** make the live lane spend-ready on node3.

### Node2 / balance path
- Rerouting to `node2.demos.sh` removed the proxy-start blocker.
- The bounded live publish attempt then failed immediately with an insufficient-balance confirmation error.
- At the same time:
  - colony/API balance reported `1000 DEM`
  - raw chain balance on node2 reported `0 DEM`
  - raw chain balance on node3 reported `1000 DEM`
- Treat this as upstream node/API state inconsistency, not operator-logic failure.

## What must be true before `uw66.1` resumes

Resume the bounded live publish lane only when **both** are true:

1. The active RPC node is explicit in the proof output, and DAHR/Web2 startup on that node is no longer failing for the chosen attestation source.
2. `check-publish-readiness.ts` and `check-publish-visibility.ts` no longer show a balance-truth divergence between colony/API balance and raw chain balance on the active RPC for the same wallet.

## Intended operator behavior

- If runtime truth shows node/API balance divergence, mark the lane blocked upstream.
- Do **not** keep brute-retrying spend-bearing writes just because one surface still reports a positive balance.
- Harden the truth surface first, then rerun the bounded live lane once the preconditions are explicit and green again.
