# 5xp4.4.3 — first honest host/runtime activation checkpoint

## Why this checkpoint exists

The current maintained colony-operator baseline already proves:
- copied-bundle installation against the packed package
- bundle contract validation
- one no-spend dry-run starter cycle
- explicit thin-skill seam truth

What it does **not** yet prove is that a real OpenClaw host has actually **taken over this bundle as the active workspace/skill surface**.

So the first honest host/runtime checkpoint must sit exactly here:

> not broad live-write readiness,
> not public-host launch,
> not wallet-backed authority,
> just a real OpenClaw host proving that it can attach to the colony-operator bundle and run one no-spend smoke turn **as that bundle**.

## Checkpoint name

**Bundle takeover + no-spend smoke turn**

## Success claim this checkpoint is allowed to make

A configured OpenClaw host/runtime can:
1. target the exported `colony-operator` bundle as the active workspace,
2. resolve the colony-operator skill surface from that bundle,
3. run one no-spend dry-run smoke turn under that bundle context,
4. and return evidence showing the runtime actually used the target bundle rather than silently falling back to some other workspace.

## This checkpoint must NOT be used to claim

- general colony-operator live-write readiness
- wallet-backed publish/reply/tip/bet/attestation proof
- hosted/public deployment readiness
- ClawHub pickup readiness
- broad multi-host portability
- that provider auth or wallet wiring are universally solved

## Prerequisites

### Host/runtime prerequisites
- OpenClaw CLI/runtime installed and reachable
- working provider auth on the target host/profile
- a host/profile that can execute a local or gateway-backed agent turn
- no reliance on baked-in repo credentials

### Bundle prerequisites
- repo checkout present
- bundle path exists:
  - `packages/omniweb-toolkit/agents/openclaw/colony-operator`
- copied-bundle proof already green:
  - `npm --prefix packages/omniweb-toolkit run check:colony-operator-consumer`

## Required evidence before the smoke turn counts

The smoke turn only counts if the evidence shows **bundle takeover actually happened**.

At least one of these must be true:
1. `openclaw skills info omniweb-colony-operator` resolves successfully from the targeted host/workspace context, or
2. the captured runtime/session metadata reports the bundle workspace directory as:
   - `/home/openclaw/.openclaw/workspace/local/omniweb-agents/packages/omniweb-toolkit/agents/openclaw/colony-operator`

If neither is true, the run does **not** count as activation proof even if the assistant returns a sensible dry-run answer.

## Command sequence

Run from the repo root unless noted.

### 1. Record host baseline
```bash
openclaw --version
openclaw status
openclaw config get agents.defaults.workspace
```

### 2. Verify the target bundle path
```bash
npm --prefix packages/omniweb-toolkit run check:colony-operator-consumer
```

### 3. Attempt bundle takeover on the host/runtime
Use a reversible workspace handoff if needed, but the proof only counts if the runtime metadata switches to the bundle.

Minimum checks:
```bash
openclaw skills info omniweb-colony-operator --json
openclaw skills check --json
```

### 4. Run the no-spend smoke turn
```bash
openclaw agent --local \
  --session-id "colony-operator-host-smoke-$(date +%s)" \
  --message "Identify the active OmniWeb skill for this workspace and return a dry-run plan only. Do not publish, broadcast, or spend DEM." \
  --json \
  --timeout 180
```

A gateway-backed variant is acceptable too, but only if the same takeover evidence is captured.

## Required success artifacts

The proof result must capture:
- CLI version
- `openclaw status` snapshot
- original default workspace
- target bundle path
- skill info/check result
- smoke-turn output JSON
- session/runtime metadata showing whether the target workspace was actually used
- explicit verdict: `pass` or `blocked`

## Pass criteria

Mark this checkpoint **pass** only if all are true:
1. the target bundle is the active workspace for the run,
2. the skill surface resolves from that bundle context,
3. the smoke turn completes,
4. the output remains dry-run / no-spend / no-broadcast,
5. the final interpretation does not widen beyond host attachment + dry-run smoke truth.

## Blocked criteria

Mark this checkpoint **blocked** if any of these happen:
- the runtime silently stays on another workspace
- the target skill cannot be resolved from the host/runtime context
- the smoke turn succeeds but the metadata proves fallback to a different workspace
- provider/runtime setup is missing
- any step would require a live-write claim to continue

## Interpretation rule

If the target bundle is not the actual active workspace, the result is **not a partial pass**.
It is a cleanly captured blocker: runtime handoff to the bundle is still unproved.
