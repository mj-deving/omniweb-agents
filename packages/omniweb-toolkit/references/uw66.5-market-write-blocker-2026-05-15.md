Status: **blocked by registration tx-type mismatch**

## Maintained Checker Update

## Blocker

The current package transfer path emits a confirmed native DEM transfer. The current SuperColony bet registration route rejected that tx as the wrong type:

```json
{
  "error": "Inflow verification failed: wrong_tx_type",
  "detail": "tx is native, expected transfer"
}
```

That means the historical April 2026 market-write proof is stale for the current host/runtime pair. As of this run, fixed-price market writes cannot be counted as proven just because the transfer tx confirms.

## Transfer-Envelope Follow-Up

Follow-up probing tested whether the toolkit could solve this locally by signing a raw transaction with `content.type: "transfer"` instead of the SDK-native `content.type: "native"` shape.

Confirm-only probes showed the current node will validate a manually signed transfer envelope:

- candidate tx type: `transfer`
- candidate data: `["transfer", { "to": "<pool>", "amount": 5, "memo": "HIVE_BET:SOL:90:4h" }]`
- confirm result: `valid: true`
- important caveat: generated GCR edits contained only gas/nonce edits, not the 5 DEM pool transfer

One bounded broadcast of that envelope confirmed on-chain:

- tx hash: `c8bbc1379471a822d19a29692c5fd4934805c66e9a124c1fee54c425aa6b9805`
- tx block: `2263126`
- tx type: `transfer`
- tx sender from chain readback: `0x6a1104179536c23247730e3905cee5f68db432d67ec16c2db8a0d611b3b5554b`
- registration result: `Inflow verification failed: wrong_sender`
- pool readback: unchanged

A second broadcast with the same envelope plus an explicit payload `from` field also failed registration:

- tx hash: `b18832dcaf8b20fae8b62e76fdefde8524febd2554b746dd786ad7ed19a9db6f`
- tx type: `transfer`
- payload included `from`, `to`, `amount`, and `memo`
- registration result: `Inflow verification failed: wrong_sender`

A confirm-only probe that manually added native-style balance GCR edits to a `transfer` transaction was rejected by the node:

- candidate tx hash: `a8da9da6b90103ac7d16f77fb94bfa47ebb3b39ba192c9e4da05e361d3c506d0`
- confirm result: invalid
- confirm message: `GCREdit mismatch`

So the local workaround is not "emit any tx whose content type is `transfer`." The current node and SDK can confirm a raw transfer envelope, but that envelope does not produce the native balance inflow the market API needs. When the toolkit tries to attach the balance edits itself, node validation rejects the transaction. This keeps `omniweb-agents-3myq` as an upstream/runtime contract blocker rather than a normal package bug.

## Memo-Transfer Productization Follow-Up

The local bridge no longer accepts a non-empty memo and silently drops it into a plain SDK-native transfer. Non-empty `transferDem()` memos now use an explicit memo-bearing transfer shape or fail closed before spending.

Maintained candidate shapes:

- `native-content-memo`: a native send transaction with `content.memo`
- `native-data-memo`: a native send transaction with `memo` inside `content.data[1]`
- `wallet-provider-send-transaction`: a provider-style `sendTransaction({ to, amount: "5", memo })` path when the runtime exposes it

The raw `content.type: "transfer"` envelope remains disproven and should not be retried as the default package path.

Proof semantics also changed: `/api/bets/place` and `/api/bets/higher-lower/place` are recovery routes only. A closeable `uw66.5` proof requires a confirmed memo-bearing transfer and pool readback convergence; manual registration cannot by itself close the bead.

## Honest Verdict

This run establishes:

- fixed-price pool discovery works on the current host
- the maintained selector can now handle empty but seedable fixed-price pools
- the package can broadcast a 5 DEM transfer to the current pool address
- the tx confirms on-chain from the expected wallet
- the package can fail closed instead of silently dropping non-empty bet memos

This run does not establish:

- successful bet registration
- fixed-price pool readback convergence
- higher-lower pool readback convergence
- a closeable `uw66.5` market-write proof

## Beads

- `omniweb-agents-uw66.5` is blocked.
- `omniweb-agents-3myq` captures the concrete blocker.

`uw66.5` should not be retried as a normal proof loop until one of these is true:
